# Scoped Live Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Native execution in the current checkout and one final independent review are already selected. Steps use checkbox syntax for tracking.

**Goal:** Produce a bounded, read-only Android folder preview using live metadata and capture-day evidence, without saving photographs or updating import state.

**Architecture:** Resolve explicit folder roots through the metadata-only interface, enumerate their inventory, collect bounded capture observations in a deterministic order, and call the existing pure planner. A thin CLI owns one device session and a new report bundle, preserving partial evidence and cancellation priority.

**Tech Stack:** Windows, C#/.NET 10, existing MediaDevices 2.0.0 and MetadataExtractor 2.9.3, System.Text.Json and xUnit. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-16-scoped-live-preview-design.md` (user-approved 2026-10-16).

## Global Constraints

- Every run requires an explicit device, at least one folder, a read limit, one boundary source and a new report directory.
- The limit controls content-open attempts, including failures, rather than successful parses.
- Attempt at most the configured number; no automatic retries or full-file fallback.
- Driver read-ahead can exceed that budget in USB traffic.
- Keep the normal `probe` metadata-only, `exif` limited to 1–3 explicit paths, and `plan` strictly offline.
- Capture days use DateTimeOriginal without timezone shifting or filename/modification-time fallback; reuse current parser policy.
- No hardware reads are included in implementation. No media saves, phone writes, configuration/checkpoint writes, importer, cache, resume or iPhone work.
- Use the existing feature branch/current checkout, Markdown tracking, native implementation and one final independent review. Do not merge or push.

## Review Focus

1. A root `Camera` must not include sibling `Camera2`, differently cased aliases or provider-returned paths outside the selected tree (Task 1).
2. An open failure, source-metadata mismatch or parser failure consumes its attempt; neither retries nor filtering by guessed age can expand the budget (Task 2).
3. A concurrent creator of the output directory must cause refusal even if the directory is empty, before any USB content is accessed (Task 3).
4. Cancellation raised during output/cleanup failure retains exit 130 and completed evidence; cleanup cannot leave a complete claim (Tasks 3–4).
5. Empty/unsupported-only folders and limit exhaustion must produce honest completeness and offline-readable reports, with no fabricated capture rows (Task 4).

## File and interface map

- `Services/DeviceFolderScope.cs`: validate requested paths and resolve canonical directory entries through ancestor listings.
- `Services/MetadataProbe.cs`: retain current entry point; add scoped-root traversal with containment checks.
- `Services/BoundedCaptureCollector.cs` and `Models/CaptureCollectionResult.cs`: schedule attempts and preserve evidence/counters, without owning the session.
- `Reporting/PreviewBundle.cs` and `Models/LivePreviewManifest.cs`: reserve exclusive report output and write the four artifacts.
- `Services/LivePreviewRunner.cs`, `Models/LivePreviewOptions.cs`, `Cli/LivePreviewCli.cs`: orchestration, arguments and lifecycle; route from `Program.cs`.
- Tests: `DeviceFolderScopeTests.cs`, `BoundedCaptureCollectorTests.cs`, `PreviewBundleTests.cs`, `LivePreviewCliTests.cs`; extend existing fake devices only where the new behavior needs it.
