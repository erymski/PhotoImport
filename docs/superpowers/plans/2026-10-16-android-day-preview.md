# Android Capture-Day Reporting and Offline Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers: executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Report capture calendar days for bounded JPEG/HEIC/DNG reads and preview day-based eligibility from local reports without copying media or updating state.

**Architecture:** Share an EXIF directory-to-day resolver while preserving the existing JPEG exact-time diagnostic. Extend the explicit content capability to return source provenance, then join versioned capture reports with an inventory in a pure planner. A separate offline CLI routes before any device provider is constructed.

**Tech Stack:** C#/.NET 10 Windows; MediaDevices 2.0.0; MetadataExtractor 2.9.3; System.Text.Json; xUnit. No new dependencies.

**Spec:** [approved design](../specs/2026-10-16-android-day-preview-design.md). This additive preview does not implement the importer or replace the deferred enrollment/configuration milestone.

## Global Constraints

- Use the recorded capture calendar day without PC-timezone or UTC conversion; no DateTime/filename/file-date fallback.
- Device reads remain explicit: 1–3 paths, 256 KiB application bytes per object, no full-file fallback or saved image bytes. Driver read-ahead may exceed this cap on USB traffic.
- `plan` reads local JSON only: no USB discovery/content access, destination inspection, downloads, configuration writes, or checkpoint changes.
- PNG/TIFF/unproven capture sources stay visible as unresolved; do not infer absence from a truncated prefix.
- Preserve metadata-only `IPhotoDevice`, JPEG command syntax, existing report fields where practical, partial results, and cancellation priority.
- Current checkout and `feat/metadata-probe`; native execution, TDD, one independent final review. Markdown tracking only. No Beads or Ponytail.
- The phone is available for a later agreed hardware validation, but this implementation run does not read it.

## Review Focus

- Dates split across EXIF directories: preserve association for instants; same-day time/offset differences must not reject a valid day.
- Maker-note failures versus broken capture/container data: only unrelated Apple maker-note errors may become warnings.
- Capture reports from another device or changed source: never silently join by filename/path alone, including legacy reports without size evidence.
- Same-day checkpoints: distinguish a manually completed day from tracked boundary keys; deleting PC copies cannot change selection.
- Offline input/output failures: malformed/partial reports, duplicate observations, cancellation and output aliases must not cause phone access or overwrite an input.

### Task 3: Pure source association and day-cutoff planner

**Files:** Create `Models/DayCheckpoint.cs`, `Models/PreviewReport.cs`, `Models/CaptureReportInput.cs`, `Services/DayPreviewPlanner.cs`, `Services/BoundaryKey.cs`, and tests `DayPreviewPlannerTests.cs`. Keep fixture builders in `tests/PhotoImport.Tests/Fakes/`.

**Interfaces:** `DayCheckpoint(int SchemaVersion, string DeviceId, DateOnly CutoffDay, string BoundaryMode, IReadOnlyList<string> BoundaryKeys)`; schema 1, modes exactly `completedDay` or `tracked`. `CaptureReportInput(int? SchemaVersion, DeviceInfo Device, string CompletionStatus, IReadOnlyList<JpegExifFileResult> Files)` carries parsed report evidence, with null schema meaning legacy unversioned diagnostics. `DayPreviewPlanner.Build(ProbeReport inventory, IReadOnlyList<CaptureReportInput> captures, DayCheckpoint checkpoint, CancellationToken token) -> PreviewReport`. `BoundaryKey.Create(string deviceId, PhotoMetadata photo, DateOnly captureDay) -> string` computes uppercase SHA-256 of UTF-8 JSON array `[deviceId, canonicalPath, unsignedSize, "yyyy-MM-dd"]`; source size is required. This is a metadata fingerprint, not media hashing.

`PreviewReport` contains schema version 1, inventory device/scope, checkpoint, per-file decisions, input problems, warnings, overall completeness, selected count/known-byte total/unknown-size count/unresolved count. Rows contain canonical source path, nullable size/day/key, decision (`eligible`, `older`, `alreadyImported`, `unresolved`) and reason. Use `decimal` for aggregate byte totals to avoid unsigned sum overflow. Unknown sizes count across inventory rows; no path or size guess creates a key. Pure input-contract violations throw `PreviewInputException : FormatException`; per-object evidence problems remain report rows/problems.
